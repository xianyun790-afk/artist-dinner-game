# 实际体验与边界排查 · 2026-11-10

本次使用独立浏览器存档 `slot=qa-followup-1110`，通过真实 NIA 与内网 TTS 验证。所有对话由打字提交，没有录制真人麦克风，也未做主观听感盲测。

## 发现与修复

1. 继续说话时重复的旧 final 可能抢先提交：新语音段等待新识别结果，不再重启旧句的发送计时；迟到 final 与浏览器自动重启保留接话余量。
2. 语音预取槽位存在竞争：等待者醒来后重新检查容量，限制最多两个合成请求；队列播放顺序及取消保持有效。旧逻辑同一可控场景峰值为 3，修复后为 2。
3. 页面隐藏会清掉画作回忆快照：停止播放时保留已有呈现内容，冻结迟到回调；返回后仍可退出收框入回忆。
4. 群聊要求安静看画时没有初始快照：在静默早退前也记录本次问题与画作，允许无讲解收藏。
5. 退出画作后角色仍以为还在画里：本轮请求增加餐桌／画作场景及受限作品 ID，最新界面状态覆盖历史描述，允许随时换话题。另收紧群聊的接话要求，避免每位角色都追加“你呢”。
6. 莫奈聊天提到植物“睡莲”会误开画：玩家主动提作品的行为保留；助手单独提到植物时不再自动开画，明确作品称呼仍可进入。

## 额外发现

在餐桌上提出新话题后，角色仍根据历史看画记录说“画面已经铺开在大家面前”，并劝玩家不要换话题。实际界面已经退出画作。保留修复前证据 `scene-context-before.txt`、`scene-context-before.png`，为本轮模型补充受限的当前场景信息并优先处理最新话题。

场景修复后同样的新话题得到“我想去水边坐坐，看睡莲在风里轻晃的影子”等直接回答，已不再要求继续看旧画，见 `scene-context-after.txt`。这也暴露出助手裸词“睡莲”的植物歧义，进一步收紧助手自动触发条件。

## 验证边界

浏览器自动化创建另一后台标签页不会使原页面的 `document.hidden` 变为 true，因此不把该操作当作真实隐藏状态验收。隐藏／恢复、识别修正、迟到结果与预取竞争由可控时序回归测试验证。网页操作覆盖实际模型、音色、停止、字幕、画作、收框、归档与群聊。
