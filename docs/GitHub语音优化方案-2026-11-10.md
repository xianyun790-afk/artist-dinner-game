# GitHub 语音交互方案与本次实现

2026-11-10｜余光 AFTERGLOW

核查 GitHub 官方仓库与源文件后，本次借鉴架构做法，自行编写适配现有 React／NIA／内网音色网关的实现；没有复制第三方源码或新增大型运行框架。

| GitHub 项目 | 可借鉴的方案 | 本次采用的部分 |
| --- | --- | --- |
| [Pipecat](https://github.com/pipecat-ai/pipecat)／[TTS 服务](https://github.com/pipecat-ai/pipecat/blob/main/src/pipecat/services/tts_service.py) | 文本聚合、每轮语音上下文、取消与清理 | 首段仍快速启动；后续片段上限由 48 扩为 96 字，优先保留完整句子；保留两段预取和单通道播放 |
| [LiveKit Agents](https://github.com/livekit/agents)／[语音示例](https://github.com/livekit/agents/blob/main/examples/voice_agents/basic_agent.py) | 将话轮、打断和误打断恢复分别处理 | 将识别结果汇总为一个用户话轮；停止旧轮、清理音频和恢复倾听分别处理 |
| [Pipecat Smart Turn](https://github.com/pipecat-ai/smart-turn) | 用音频信息判断用户是否真正说完 | 作为后续实时链路候选；本次未安装或声称接入语义判停模型 |

## 已完成

- **四种受限表达**：平静、好奇、温暖愉快、克制认真。同一状态发送到对白提示与语音指令；普通不同意见不会直接触发不悦，修复与安静请求回到平静。人物声线不随情绪更换。
- **表现力音色推荐**：有兼容音色时，新推荐优先豆包 expressive；否则仍选 standard。已保存的手动音色不覆盖。保存的 standard 不支持当前网关的风格指令，仍保留其声音并使用轻微节奏调整；要采用新推荐，可在原有声音设置使用“采用推荐音色并试听”。
- **会话内音频缓存**：相同服务、模型、音色、文本、语速、音高和语气的成功合成可复用，最多 16 条／4 MB／60 秒，刷新连接或退出组件清空；不写入存档或磁盘。取消、失败和迟到音频不缓存，解码使用独立副本。
- **较完整的后续分句**：首段保留低等待策略，后续优先完整句子，减少长句中间重新起腔；不是将文字逐字送入 TTS。
- **识别接话余量**：汇总浏览器最终识别片段，保留 360 ms 的继续说话余量；中途修正、浏览器自动结束和重启不会直接丢掉已确认片段。迟到结果不进入新一轮。
- **一键打断并继续说**：回复期间原麦克风按钮显示“打断，接着说”，停止旧回复后重新倾听。仍支持独立的停止按钮。
- **分阶段计时**：只在内存与开发用 DOM 属性中保留首分句、首段准备、首音计时。语音输入有浏览器 speechend 事件时才记录浏览器估计的停口至首音；打字输入不冒充麦克风实测。群聊后续角色的计时单独标为 `group-followup`，不把前一人的整段发言算成模型延迟。

当前内网服务公开前端仅发现 `/api/tts` 整段 base64 音频响应，未发现受支持的音频流接口。本次没有虚构流式地址，也没有将浏览器识别直接当作带可靠回声消除的实时采集。**免按键语音插话、连续音频流、真正语义判停与 NIA 会话复用尚未接入**；需要网关或实时语音后端提供相应能力。现有用户无须配置新的供应商密钥即可使用本次已完成部分。

长期记忆未扩展：群聊不导入任何人物私聊的情绪、内容或记忆。原始上传资料、参考图不进入表达指令。画作全屏、纯台词字幕、退出收框大小与动画时长保持现有行为。

## 验证

自动测试覆盖表达边界、后端输入校验、分句、识别修正与自动重启、缓存隔离与取消、计时口径；浏览器另测试真实 NIA 与音色服务，具体结果及限制见 `verification/voice-naturalness-1110/README.md`。试听样本只用于比较标准版与表现力版，不把单个 TTS HTTP 响应时间当成完整对话延迟或自然度评分。
