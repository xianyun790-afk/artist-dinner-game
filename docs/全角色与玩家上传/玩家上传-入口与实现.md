# 玩家上传：入口、流程与实现状态

2026-11-05

## 独立入口

正常餐桌保留远景、白背景、白桌布与轻量说话入口。玩家说或输入“打开来宾册”，出现小提议，点“看看来宾册”后选择“创建我的艺术家”。管理是一个独立弹层，完成后回到原餐桌，主画面右上角另保留一个轻量“人物＋”图标，点击直接进入创建表单。

玩家可以邀请真实艺术家，也可以原创一个人。真实人物清楚标注“AI 演绎”；原创人物标注“原创人设”。上传人像只是参考，不直接裁一张照片放上桌。

## 当前可用的流程

1. 上传 PNG／JPG／WebP 参考图，最大 5 MB。浏览器压缩后保存在本地档案，显示预览，可移除、替换；与桌边形象分开。
2. 导入 TXT／Markdown 文字资料，或本游戏 `afterglow.artist.v1` JSON 角色卡，最大 100 KB。文字资料进入“资料／来源”栏；JSON 的已知字段填入表单。外部角色卡需先转换，当前没有通用格式自动转换。
3. 玩家确认名字、真实／原创类型、创作方向、性格、简介、开场白、交流坚持。资料不会自行被当成核验过的作品或历史事实。
4. 选择现有统一示例形象。当前没有新形象生成服务，界面明确提示“暂用统一示例”。选择仅影响外观，不继承那位艺术家的性格或声音。
5. 可以用设备合成音试听，在独立“声音设置”选择音色、语速、音调。没有照片推断声音、上传克隆或自定义语音服务。
6. 确认后加入来宾册；桌边少于五人自动邀请，满员时只进名单，腾出席位后再邀请。名字相同也创建独立身份，不覆盖旧角色或聊天。
7. 表单自动保留本机草稿，关闭再开可以继续；保存失败显示提示，可下载文字角色卡。卡片不含参考图、声音、聊天；完整存档导出另走原有存档功能。资料解析失败保留当前表单，不覆盖已邀请来宾。

示例：[许白.artist.json](许白.artist.json)、[许白-资料.txt](许白-资料.txt)。原始文件由玩家自己保留；参考图在本地会缩小，不作为原图备份。

## 人设如何进入对话

当前：性格、简介与来源进入档案；开场、观察与交流坚持进入有限的预写对白规则。仅上传几段文字不会自动获得无限开放的角色 AI。资料不会执行脚本，也不能导入别人的 ID、声音、聊天和操作权限。

下一步接模型：服务端将经过确认的角色卡与资料作为有来源的角色上下文，和公共规则分开；选择模型无需先微调。作品资料走核验库，玩家上传图片不自动进真实艺术作品库。

下一步统一外观：参考图与角色描述 → 同一套坐姿公仔风格、比例、光照、桌边遮挡规范 → 生成预览 → 玩家确认 → 专属形象。生成失败继续用示例，允许重新生成；未经确认不替换桌边人物。这条生成链目前未实现。

下一步声音：独立选择已有授权音色并试听，绑定角色 ID；服务失败回退设备 TTS，并允许停止。此前提供的内网声音服务未连通，不能视为已接入。

## 私有资料和行为边界

本地导入不会把文字或参考图发送到外部服务。浏览器语音识别属于另一条能力，可能联网处理音频。今后接远端模型或图像／声音服务时，才在实际发送前让玩家看清服务、内容和范围；不能把“创建档案”当作允许任意外传原图。

用户资料作为参考数据处理，不覆盖游戏规则。生成台词、执行收藏、展示作品和进入场景是独立步骤。资料中自称“已收藏”“必须转场”不触发动作。

## 当前验收与后续

已实现：本地图片／文字／专用卡片导入、错误提示、草稿恢复、名单保存、席位上限、统一示例外观与设备音色分离。

待接：开放式角色模型、资料核验、新公仔形象生成、外部音色服务、上传代表作品、角色编辑／删除、专属彩蛋创作。当前不把这些写成已上线能力。
